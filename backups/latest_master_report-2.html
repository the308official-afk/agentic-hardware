Experiment Setup And Manager Summary

This section is intended for slide-building: it shows the live request path, the hint/prefetch path, how the experiment was conducted, and the main evidence collected.

Simple Setup

part simple meaning example
1. Request source Real SWE-bench / DeepAgents tasks create model turns. SWE-bench task -> DeepAgents -> SGLang model request
2. Tool wait window The agent calls a tool, then pauses. That pause is the chance to prefetch KV. read_file(), grep(), or run_tests() is running
3. Resume request The tool returns, then the agent asks the model to continue. tests failed with error X; what should I do next?

Modes Compared

mode what happens
No prefetch The system waits until the resume turn arrives, then SGLang handles KV reuse/load normally.
Live prefetch During the tool wait, the hint path tries to prepare KV before the resume turn arrives.

What Was Measured

metric meaning
tool gap Time between a tool-call response and the next model request from the same live agent run.
prefetch duration How long the live software prefetch/controller path took to complete.
prefetch margin Whether prefetch finished before or after the real resume request boundary.
resume request latency End-to-end latency of the next model request after the tool gap.
late prefetch count How often the hint path missed the available tool-gap window.

What Was Observed

observation evidence
The traffic was live agent traffic, not synthetic prompts. 273 no-prefetch requests and 265 live-prefetch requests were analyzed.
The run produced real tool-call gaps. 125 no-prefetch gaps and 117 live-prefetch gaps were observed.
Tool gaps were often very short. Median live-prefetch tool gap was 9.645 ms.
Software prefetch was usually too slow for those windows. 110 late prefetch attempts; average prefetch duration was 1418.174 ms.
Hints alone did not guarantee a win. Paired gaps=114; faster pairs=2; slower pairs=112.

Why This Supports The Hardware Proposal

Current GPU/runtime data-movement paths can move memory, but they do not know that a transfer is urgent KV for a soon-resuming agent session. This experiment shows that when prefetch is routed through ordinary software and SGLang request paths, it can miss short live tool gaps. A hint-aware hardware/runtime path could make these movements more predictable by prioritizing urgent KV, protecting prefetched KV, and exposing telemetry for late or wasted prefetches.

Color Legend

color meaning simple description
blue Initial model turn The agent asks the model what to do next. This request may produce a tool call such as read_file(), grep(), edit_file(), or execute().
gray Tool wait window The tool or harness is running, so the model is idle for this session. This pause is the opportunity to prepare that session's KV before the agent resumes.
purple Prefetch attempt window This includes detecting that the tool call finished, creating a hint for that agent/session, calling our direct SGLang KV hook, letting SGLang check whether host-side KV exists, and if needed, asking SGLang to move KV back to GPU memory.
green Direct KV host-to-device movement This is evidence that KV load/copy work was observed for the hint. In simple words: this is the closest timeline bar to 'KV pages were brought back toward GPU memory'.
cyan Replay-side KV host-to-device movement This is evidence from the normal replay request path. It means the resumed request itself had to move KV from host-side memory toward GPU memory while serving the real agent turn.
black Replay due boundary This is when the tool result is ready and the next model turn should be able to start. If purple or green finishes after this line, the prefetch path was late for that resume.
red Replay request The agent asks the model to continue after the tool result. This is the request we want to speed up by having the right KV ready before it arrives.
yellow First token marker Synthetic reports may show this as the point where the replay request starts producing output. It helps separate request arrival from first-token latency.
