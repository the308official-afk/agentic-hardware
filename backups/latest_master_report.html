This milestone keeps real SWE-bench/DeepAgents prompt content, but controls the timing. That gives us a cleaner hardware-style experiment: same kind of agent text, known wait windows, known cache pressure, and direct SGLang KV-hook attempts.

part simple meaning

2. Controlled wait Replay Turn A, then impose a chosen tool-wait window such as 100 ms or 500 ms.
3. Cache pressure Send filler requests during the wait to make KV residency harder.
4. Direct KV hint In prefetch modes, issue the marked direct-load request during the wait.
5. Resume Send Turn B at the scheduled resume time, even if the hint is still running.

How To Read The Timelines

Purple means the prefetch attempt ran. Green means that attempt had attributed direct KV host-to-device movement. Purple without green means the hint ran, but no matching HtoD load was observed for that displayed gap.

The timeline uses a symlog full-replay view. It compresses very long replay requests so red bars can extend to their true end while the important activity around 0 ms remains visible.

One Row In Plain English

Each timeline row is one tool-wait episode: model turn, tool call, wait, optional prefetch, then model resume.

step timeline color simple meaning
1. Ask model what to do blue bar model turn before the tool call
2. Model says to call a tool end of blue bar the model turn hands work to a tool
3. Tool runs gray bar read_file(), grep(), run_tests(), etc. is happening
4. Agent waits gray bar this wait is the prefetch opportunity
5. Tool returns black vertical line the next model turn is due
6. Agent asks model again red bar resume request after the tool result
During steps 3/4, if prefetch is enabled purple bar our software prefetch attempt runs during the wait
Inside the purple window, if KV moved green bar direct SGLang KV host-to-device movement was observed for that hint
Inside the red replay request, if KV moved cyan bar the real replay request itself performed host-to-device KV movement

Color Legend

color meaning simple description
blue Initial model turn The agent asks the model what to do next. This request may produce a tool call such as read_file(), grep(), edit_file(), or execute().
gray Tool wait window The tool or harness is running, so the model is idle for this session. This pause is the opportunity to prepare that session's KV before the agent resumes.
purple Prefetch attempt window This includes detecting that the tool call finished, creating a hint for that agent/session, calling our direct SGLang KV hook, letting SGLang check whether host-side KV exists, and if needed, asking SGLang to move KV back to GPU memory.
green Direct KV host-to-device movement This is evidence that KV load/copy work was observed for the hint. In simple words: this is the closest timeline bar to 'KV pages were brought back toward GPU memory'.
cyan Replay-side KV host-to-device movement This is evidence from the normal replay request path. It means the resumed request itself had to move KV from host-side memory toward GPU memory while serving the real agent turn.
black Replay due boundary This is when the tool result is ready and the next model turn should be able to start. If purple or green finishes after this line, the prefetch path was late for that resume.
red Replay request The agent asks the model to continue after the tool result. This is the request we want to speed up by having the right KV ready before it arrives.
yellow First token marker Synthetic reports may show this as the point where the replay request starts producing output. It helps separate request arrival from first-token latency.
